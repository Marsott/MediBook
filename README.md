# MediBook

Web εφαρμογή διαχείρισης και προγραμματισμού ραντεβού μεταξύ ασθενών και ιατρών. Το έργο αναπτύσσεται στο πλαίσιο διπλωματικής εργασίας, με **Node.js** στο backend και **React** στο frontend.

## Περιγραφή

Το MediBook επιτρέπει σε έναν ασθενή να αναζητά ιατρούς με βάση την ειδικότητα και την περιοχή, να βλέπει τη διαθεσιμότητά τους και να δεσμεύει διαθέσιμη ημέρα και ώρα για ραντεβού. Ο ασθενής μπορεί επίσης να ακυρώνει ραντεβού και να προβάλλει το ιστορικό και το πρόγραμμά του ανά εβδομάδα ή μήνα.

Για κάθε εγγεγραμμένο ιατρό τηρούνται τα βασικά προσωπικά και επαγγελματικά στοιχεία, τα στοιχεία επικοινωνίας, η ειδικότητα, η περιοχή του ιατρείου και το διαθέσιμο πρόγραμμά του.

## Στόχοι της εφαρμογής

- Ασφαλής εγγραφή και σύνδεση ασθενών με χρήση ΑΜΚΑ και κωδικού πρόσβασης.
- Αναζήτηση ιατρών ανά ειδικότητα και περιοχή.
- Προβολή διαθέσιμων ημερών και ωρών ανά ιατρό.
- Κράτηση ραντεβού με καταχώρηση του λόγου επίσκεψης.
- Ακύρωση προγραμματισμένου ραντεβού από τον ασθενή.
- Προβολή των ραντεβού του ασθενούς σε εβδομαδιαία και μηνιαία μορφή.
- Αποφυγή διπλής κράτησης της ίδιας χρονικής θέσης.

## Ρόλοι χρηστών

### Ασθενής

Ο ασθενής μπορεί να:

1. Δημιουργήσει λογαριασμό με το ΑΜΚΑ και έναν κωδικό πρόσβασης.
2. Συνδεθεί με ασφάλεια στην εφαρμογή.
3. Επιλέξει ιατρική ειδικότητα και επιθυμητή περιοχή.
4. Δει τους ιατρούς που αντιστοιχούν στα κριτήρια αναζήτησης.
5. Επιλέξει ιατρό και να δει τη διαθεσιμότητά του.
6. Κλείσει διαθέσιμο ραντεβού, αναφέροντας τον λόγο επίσκεψης.
7. Ακυρώσει μελλοντικό ραντεβού.
8. Προβάλλει τα ραντεβού του ανά εβδομάδα ή μήνα.

### Ιατρός

Για κάθε ιατρό αποθηκεύονται:

- ΑΜΚΑ
- Ονοματεπώνυμο
- Ιατρική ειδικότητα
- Στοιχεία επικοινωνίας
- Περιοχή και στοιχεία ιατρείου
- Διαθέσιμες ημέρες και ώρες

Η διαχείριση των στοιχείων και της διαθεσιμότητας των ιατρών θα εξειδικευτεί σε επόμενη φάση των απαιτήσεων.

## Προτεινόμενη τεχνολογική στοίβα

### Frontend

- React
- React Router για την πλοήγηση
- Fetch API ή Axios για επικοινωνία με το backend
- Βιβλιοθήκη ημερολογίου, εφόσον κριθεί απαραίτητη

### Backend

- Node.js
- Express.js για το REST API
- JSON Web Tokens ή ασφαλή server-side sessions για authentication
- Βιβλιοθήκη ασφαλούς κατακερματισμού κωδικών, όπως Argon2 ή bcrypt

### Βάση δεδομένων

Προτείνεται σχεσιακή βάση δεδομένων, όπως **PostgreSQL**, επειδή οι κρατήσεις απαιτούν σαφείς σχέσεις και συναλλαγές που αποτρέπουν τις διπλές δεσμεύσεις. Η τελική επιλογή θα οριστικοποιηθεί κατά τον σχεδιασμό του backend.

## Βασικό μοντέλο δεδομένων

Οι κύριες οντότητες της εφαρμογής είναι:

- **Patient**: στοιχεία λογαριασμού και ταυτοποίησης ασθενούς.
- **Doctor**: προσωπικά και επαγγελματικά στοιχεία ιατρού.
- **Specialty**: διαθέσιμες ιατρικές ειδικότητες.
- **Practice**: στοιχεία και περιοχή ιατρείου.
- **AvailabilitySlot**: διαθέσιμη ημέρα και ώρα ενός ιατρού.
- **Appointment**: σύνδεση ασθενούς, ιατρού και χρονικής θέσης, μαζί με τον λόγο και την κατάσταση του ραντεβού.

Ενδεικτικές καταστάσεις ραντεβού: `scheduled`, `cancelled`, `completed`.

## Ενδεικτικό REST API

| Μέθοδος | Endpoint | Περιγραφή |
| --- | --- | --- |
| `POST` | `/api/auth/register` | Εγγραφή ασθενούς. |
| `POST` | `/api/auth/login` | Σύνδεση ασθενούς. |
| `GET` | `/api/specialties` | Λίστα ιατρικών ειδικοτήτων. |
| `GET` | `/api/areas` | Λίστα διαθέσιμων περιοχών. |
| `GET` | `/api/doctors` | Αναζήτηση ιατρών ανά ειδικότητα και περιοχή. |
| `GET` | `/api/doctors/:doctorId/availability` | Διαθεσιμότητα επιλεγμένου ιατρού. |
| `POST` | `/api/appointments` | Δημιουργία και δέσμευση ραντεβού. |
| `PATCH` | `/api/appointments/:appointmentId/cancel` | Ακύρωση ραντεβού. |
| `GET` | `/api/appointments` | Ραντεβού συνδεδεμένου ασθενούς για επιλεγμένο διάστημα. |

Τα endpoints είναι αρχικός σχεδιασμός και ενδέχεται να προσαρμοστούν κατά την υλοποίηση.

## Ασφάλεια και προστασία δεδομένων

Το ΑΜΚΑ και ο λόγος επίσκεψης αποτελούν ευαίσθητα προσωπικά δεδομένα. Κατά την ανάπτυξη πρέπει να εφαρμοστούν τουλάχιστον τα παρακάτω:

- Οι κωδικοί δεν αποθηκεύονται ποτέ ως απλό κείμενο.
- Το ΑΜΚΑ δεν εμφανίζεται άσκοπα στο UI και δεν καταγράφεται σε logs.
- Όλα τα προστατευμένα endpoints απαιτούν έλεγχο ταυτότητας και δικαιωμάτων.
- Τα δεδομένα εισόδου ελέγχονται και καθαρίζονται στο backend.
- Η επικοινωνία σε περιβάλλον παραγωγής γίνεται αποκλειστικά μέσω HTTPS.
- Η κράτηση μιας χρονικής θέσης πραγματοποιείται ατομικά στη βάση δεδομένων, με κατάλληλο unique constraint ή transaction.
- Συλλέγονται μόνο τα δεδομένα που είναι απαραίτητα για τη λειτουργία της εφαρμογής, σύμφωνα με τις αρχές του GDPR.
